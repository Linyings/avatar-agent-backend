# 口播与图解视频分镜设计

先明确观众在每段需要理解什么，再决定画面如何组织、人物何时出现和信息如何展开。交付可供后续制作使用的分镜，而不是只有标题和动效名称的清单。

本项目的 Agent 使用 `read_skill` 读取相对资源；应用方案前读取 [项目执行约定](references/project-integration.md)，将设计映射到现有制作参数和节点。这里只读取方法，不自动开始制作。

## 输入与工作范围

- 接受文案、参考视频、已有分析报告或现有分镜。保留用户给定的事实、口吻和内容顺序；确需改写时明确区分原文与建议。
- 优先复用已经完成且证据清楚的分析。新参考需读取实际视频或可靠材料；无法访问时说明缺失部分，不假装观看。
- 先从上下文确定目标比例、用途、受众、文案、音频和可复用素材。非关键缺项采用明确标注的假设；关键输入缺失时先推进能完成的部分，再集中询问。
- 用户只要求分析或设计时，完成方案即可。实际生成、裁剪与渲染依用户授权调用可用制作工具；本技能不依赖特定软件、模型或仓库。
- 记录画面观察、机制推断、复现建议的区别。仅凭成片不能确认数字人模型、原始软件、源视频生成批次或精确图层工程。

## 工作顺序

### 1. 建立内容骨架

为文案段落分配稳定编号，标出开场、问题、解释、证据、结论和行动引导。每个候选场景写出一句可验收的目标，例如“观众能区分串行和并行”，而非“展示科技感”。

区分五种粒度：

| 粒度 | 判断依据 | 示例 |
|---|---|---|
| 章节 | 一个较大的叙事阶段 | 原理、操作、费用 |
| 场景 | 一个主要讲解目标和可持续的视觉关系 | 用两列队列解释串行与并行 |
| 镜头／布局状态 | 观众此刻主要看谁、看哪里 | 全屏人物、图解加小窗、纯图解 |
| 场内事件 | 同一关系中的逐步变化 | 新卡片出现、当前节点点亮 |
| 制作素材 | 后续独立制作或复用的输入 | 干净口播、背景、图标、图解动画 |

场景、布局、事件、素材不是一一对应。一个流程场景可以持续多句话；同一人物素材可服务多个场景；一次打勾不必成为独立视频生成任务。

### 2. 按语义决定切分

当主要讲解目标、对象关系或证据类型改变，考虑新场景；当需要直接交流、展示手势或给密集图表让位，考虑改变人物布局。只有当前节点、关键词或状态改变时，优先保留场景，在场内更新。

用两个问题复核边界：

1. 保留上一场的主图，能否清楚解释接下来的内容？能则优先复用，避免无意义重建。
2. 新信息是否造成两个竞争的视觉焦点或超出阅读容量？是则简化、分步展示或拆场。

不要按固定秒数、每句话、每个条目或每个生成文件机械切镜。章节切换也不必全部使用强转场。

### 3. 选择讲解模式与视觉规则

- **人物与图解交替**：需要人物表现、情境例子、教程或数据交替时，在人物全屏、图解加小窗、图解独占之间按内容切换。
- **固定面板持续讲解**：需要长链路推理、步骤或关系图时，开场后保持稳定信息面板和人物小窗，用信息逐步展开维持节奏。
- 可以按章节混用。比例影响布局，不决定必须使用哪种模式。

建立全片共享的背景、字体层级、颜色职责、卡片样式、人物窗口、字幕安全区、运动幅度和转场规则。根据目标播放尺寸检查可读性，不直接照搬参考的颜色、坐标、窗口比例或留白。

具体选择与动作配方见 [场景与编辑方法](references/scene-design.md)。两条参考的观察依据见 [参考案例](references/reference-cases.md)，需要追溯时再读。

### 4. 逐场设计构图与信息变化

每场明确：讲解目标、对应台词、主视觉及关系、人物状态、图层位置、保留内容、事件顺序、最终状态，以及下一场为什么要切换。

把“依次显现”“箭头动画”等泛称写成具体动作：哪个对象在对应哪句台词时发生什么变化，变化结束后留下什么。例如“说到目标时，目标卡从下方移到顶部并提亮，内容卡下移变暗”，让动作本身解释优先级。

默认保留有用上下文：流程骨架、已完成节点、比较对象和必要标签。只强调当前焦点，避免所有对象同时运动。普通换场优先替换内容区；全画面特效用于明确的强调、章节门槛或结束。

### 5. 分开人物素材与后期合成

- 人物源素材为干净的普通矩形口播，保留头肩；需展示手势时保留相应身体范围。固定机位和稳定取景按用途安排。
- 圆形、圆角矩形、位置、描边和窗口收放交给后期裁剪、遮罩和布局。不要让人物生成模型把人物直接画进小窗、讲解面板或成片字幕里。
- 以脸、头顶、肩部和必要手势确定裁剪锚点，等比缩放。窗口比例与源片不符时裁切或留边，不能非等比拉伸人像。
- 平稳讲解时保持取景稳定；确有位移时平滑纠偏，避免追踪噪声造成呼吸式缩放。人物容器从全屏收为小窗，不代表窗口内部还要持续推近人脸。
- 布局改变时沿用人物当前播放时间。人物隐藏后再出现也应读取当前正确的源时间；分段源片逐段记录入点，不能切换布局就重播。
- 指定唯一的人声来源；独立配音时人物视频轨静音。字幕独立于人物变换，不能随收窗变小或被遮挡。

### 6. 用真实口播校准时间

优先依据实际音频时长与词句对齐安排事件。只有文案时用台词触发点和估算时长，明确标记“待音频校准”，不得伪称精确同步。

区分成片全局时间、场景局部时间与人物源时间。场景、转场和事件必须落在明确区间；转场写明占用本场末尾还是与下一场重叠，防止总时长重复累计。

给主要信息留下阅读与理解时间。图解放不下时，先减少文字、拆解事件或拆场；不要用随意加速口播、延长静帧或拉伸人物视频掩盖时长不匹配。

### 7. 交付与分批

按 [分镜交付格式](references/storyboard-format.md) 输出：全片模式与风格规则、场景总表、复杂场景的事件与图层说明、素材复用和未确定项。简单场景不必重复冗长规格。

长视频先输出稳定的章节／场景索引，再按章节或场景批次细化。每批引用共享风格和素材编号，保留已完成编号、下一批起点与待解决项。按当前模型实际输出预算留出余量；不要把全片源代码、全部素材数据或重复提示词塞入一次输出，也不要把断开的 JSON 当成完整方案。

制作资产需要提示词时，为该资产提供内容、构图、动作与限制；人物源片提示词和后期合成指令分别记录。可修改提示词，重做对应资产后更新引用，保留场景与素材之间的对应关系。

## 交付前检查

- 每场有一个清楚的讲解目标；每次切换有语义或注意力理由。
- 动效表达关系，人物与主内容不争抢同一焦点；长流程不靠频繁放大人脸维持节奏。
- 在目标播放尺寸检查文字、字幕、窗口和平台遮挡区；密集画面可隐藏人物。
- 人像没有误裁、非等比拉伸或不必要的连续推近；布局切换不打断人物源时间。
- 台词覆盖完整，时间单位一致，事件与转场不越界，无意外空面板、黑帧、重复声音或源片不足。
- 分镜设计完成、素材已生成、已渲染和已观看验收是不同状态，只报告实际完成的部分。
