# 本项目执行约定

本技能默认可用，是否读取、采用哪种讲解模式由 Agent 根据本轮任务和项目内容判断。不要用“每个项目必须用此模式”的硬规则替代选择，也不需要用户先开启技能。

## 读取方法与真实素材

- 用 `read_skill`，参数 `name="talking-head-storyboard"`；读取参考文件时再传 `resource="references/scene-design.md"` 等目录内路径。
- 默认上下文只包含技能简介，正文与参考文件按需读取。不要把全部文档粘贴到制作参数里。
- 用 `avatar_inspect` 读取实际项目、输入、导演稿、素材、镜头、版本、工作流状态与工具包；参考分析见项目已有产物。技能中的两条样片属于方法依据，不代表当前项目已经上传或分析同样素材。
- 参考案例里的本机路径仅供来源追溯，容器中未必存在。不能使用它们伪造当前项目的素材路径或分析结果。

## 将方法传入真实制作

| 用户当前任务 | 接入方式 |
|---|---|
| 分析参考、讨论分镜、仅给建议 | 读取方法和真实证据，输出分析或分镜方案，不调用生成／重做工具 |
| 新项目明确要求制作 | 先读取已有需求；将本次选择的模式、场景原则、人物布局与必要例外简要合并到 `avatar_configure.direction`，保留原要求、风格、画幅及人物／动效开关，再通过现有制作工具启动 |
| 修改已有导演稿 | `avatar_edit_node` 的 F01.6 与 `director`，使用工具声明的字段和真实场景编号；保留原稿、事实与未受影响要求 |
| 调整素材、口播生成或动效内容 | 使用相应节点的 `needs` 等已声明字段，人物源素材和后期小窗分别处理 |
| 调整已组装镜头 | 使用 F10 的 `shots` 和已有素材 ID、时间及源入点；遵守当前校验与素材可用性 |
| 修改字幕、呈现或正式合成参数 | 使用对应工具允许的 `subtitles`、`presentation` 等字段，不编造未支持的参数 |

`direction` 中只保存已选用、与该项目有关的简明设计要求，不能覆盖用户原有要求或塞入整份技能。制作阶段会读取这些要求；只在聊天中说明“我用了技能”并不会自动改变工作流。

分镜模板用于组织思路，提交工具时按当前 schema 转换。已有编辑与重做采用平台现行提案流程；生成方案、提交任务、完成渲染分别报告。读取技能本身无需生成修改提案。

## 后续校准

只有文案时标记预计时间；真实配音生成后按实际时长安排镜头。素材裁剪保持比例和稳定取景，人物布局变化不重置源时间。长视频按现有的分段／分窗机制细化，保留编号引用和全片一致性。
