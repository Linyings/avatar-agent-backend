# 可交付的分镜格式

按任务复杂度使用这些字段；不要求每次生成长篇 JSON。人类审阅先用总表，需要程序消费时再映射到下游已确认的格式，不声称本格式已与某个应用接通。

## 1. 全片约定

先交付这些共享信息，逐场引用即可：

- 内容目标、目标受众、比例和发布场景；分辨率／帧率已知时记录，否则标记待定。
- 文案版本与段落编号；音频是未生成、已生成还是已完成词句对齐。
- 主讲解模式、允许的布局状态、章节边界及选择理由。
- 风格职责：背景、字体层级、颜色含义、卡片形态、人物窗口、字幕和平台安全区。
- 共享素材编号、来源和可用性；仅有制作计划的素材不可标记为已存在。
- 时间依据、转场计时规则以及尚未确认的限制。

## 2. 场景总表

| 字段 | 要求 |
|---|---|
| 场景／章节编号 | 稳定唯一，如 S01；修改内容后保留可追踪关系 |
| 台词范围 | 段落编号或准确起止句，保证全文没有遗漏或重复 |
| 时间 | 实测全局起止，或明确标注的暂估时长／台词触发范围 |
| 讲解目标与切分理由 | 观众需要理解什么，以及为何从上一场进入本场 |
| 主视觉及关系 | 具体对象、比较／流程／倒推等关系，不能只写“大字动画” |
| 人物状态 | 全屏、小窗或隐藏；形状、位置和取景要求 |
| 主要事件 | 按顺序描述建立、变化、强调和终态 |
| 衔接 | 进入／退出方式、保留层、切换范围与占用时间 |
| 素材引用 | 复用项、新制作项、需重做项及状态 |

总表避免塞入完整台词和重复风格，复杂场景另附详情。

## 3. 复杂场景详情

### 构图与图层

写出主体、背景、信息区、人物、字幕的区域和遮挡关系。使用坐标时声明单位、原点与锚点；例如“左上角为原点，x/y/w/h 为全画面归一化比例”。每个元素引用共享风格，单独记录例外。

### 事件

每个事件记录：`事件编号 → 台词锚点 → 局部开始/结束 → 对象 → 起始状态 → 动作 → 结束状态 → 是否保留`。

连续高亮要说明旧焦点如何退到普通／已完成状态。需要读完的文字留下稳定停留时间。进入、阅读、退出都属于场景时长，不能只记录动画运动本身。

### 人物与声音映射

记录源素材编号、源入点／出点、对应成片区间、播放倍率及唯一人声来源。正常口播默认原速；更改速度需符合制作目的和同步约束。

对于一段连续人物片段：

```text
t_source = source_in + (t_final - clip_final_start) * playback_rate
```

`clip_final_start` 是该源片段进入成片时间轴的起点，不是每次收窗的开始时间。人物隐藏只改变可见性，不应重置映射。使用新片段或非连续剪辑时新建映射区间。

### 转场约定

声明转场是“计入当前场景末尾”“计入下一场景开头”还是“明确重叠区间”。同一边界只由一个约定负责。相邻场景不能各自增加一遍转场时长。

若需读取下一场素材参与交叉过渡，检查源片前后余量。字幕、主声音与人物视频不必同一方式淡入淡出；逐层规定。

### 制作指令与提示词

为需要生成的资产保存 `资产编号、用途、可编辑提示词、构图限制、是否含背景/人物/文字、版本与状态`。后期的裁剪、遮罩、布局、事件和转场独立保存为合成指令。

不要把“人物在右下圆窗里讲话”直接当作人物源片的生成提示词；应生成干净人物源片，再用合成指令完成右下圆窗。

## 4. 同一内容的两种设计示例

以下为虚构的规划演示，素材尚未制作，时间全部暂估，待实际音频校准。不是参考视频实测片段。

文案：

- P01：“做一条讲解视频，哪些东西需要重新做？”
- P02：“先准备口播原片，再准备解释用的图卡，最后按台词把它们合成。修改图卡时，人物原片仍然可以复用。”
- P03：“先把内容关系讲清楚，再决定哪里需要切换画面。”

| 场景／暂估时间 | 目标与主视觉 | A：人物与图解交替 | B：固定面板持续讲解 |
|---|---|---|---|
| S01／0–5 秒／P01 | 提问：哪些素材需要重做 | 全屏人物，短问题文字 | 全屏人物，短问题文字 |
| S02／5–23 秒／P02 | 展示口播、图卡、合成的关系；标识人物可复用 | 人物收为圆角小窗；较宽内容区放流程，完成后高亮可替换图卡 | 人物收为圆窗；稳定面板内纵向铺流程，完成后高亮可替换图卡 |
| S03／23–31 秒／P03 | 从素材关系转入分镜原则 | 人物展开全屏，结论短句独立出现 | 保留人物小窗和面板，流程替换为“内容关系→画面安排” |

P02 的多个短句保留在一个场景，因为它们共同解释一套素材关系。更换图卡是场内事件，不需要再生成一条人物视频。S03 改变了讲解目标，两种模式分别用全屏交流与面板换图完成转折。

S02 的事件安排示例：

| 局部暂估时间 | 台词锚点 | 事件 | 结束状态 |
|---|---|---|---|
| 0–0.6 秒 | 从问题进入回答 | 人物收窗，内容区建立 | 人物取景稳定，正文可用 |
| 0.6–4 秒 | “口播原片” | 人物素材卡出现并强调 | 卡片保留，结束强调 |
| 4–7 秒 | “解释用的图卡” | 图卡出现，与人物素材建立汇合关系 | 两项输入都保留 |
| 7–11 秒 | “按台词把它们合成” | 输入连接到合成结果，显示结果缩略示意 | 完整关系保留 |
| 11–16 秒 | “修改图卡……原片仍然可以复用” | 图卡内容变化，人物素材卡保持；显示可复用标记 | 观众能分辨变化项与复用项 |
| 16–18 秒 | 本段收束 | 保留终态供阅读；末段按模式安排退出 | 交接到 S03 |

语句实际落点变化后必须重排事件；不能强行让音频迁就这些暂估秒数。模式 A 与 B 在构图和退出方式上不同，可复用同一信息关系和素材。

这个示例的口播源片若覆盖整段，其播放在成片 23 秒处仍应对应源映射的 23 秒处；不能因进入 S03 又从 0 秒播放。若真实素材由多段组成，则使用各自的源入点映射。

## 5. 长视频分批交付

1. 先建立章节、场景编号、文案覆盖和共享素材索引，确定总览完整。
2. 根据单场复杂度和当前模型输出额度选取本批范围，不固定每批必须多少场。
3. 每批只细化相应场景，引用共享规则，不复制全片上下文和素材正文。
4. 批次末尾记录：完成场景、下一场编号、共享规则变更、待校准时间与未解决依赖。
5. 汇总时检查文案覆盖、编号引用、素材状态、首尾状态衔接和时间范围；共享规则更新后检查受影响场景。
6. 接近输出上限时在完整场景边界结束，继续下一批。机器格式必须保持可解析，不能交付被截断的数据。

## 6. 交付状态

结尾写实际完成状态，例如：“已完成分镜设计；人物素材待生成；场景时间为估算，待配音后对齐。”如果已经制作，另写观看验证范围和具体问题。设计检查不能替代成片画面、音频及口型检查。
