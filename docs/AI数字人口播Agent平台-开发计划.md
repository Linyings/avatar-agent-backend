# 数字人口播平台开发计划 V2.2

需求基线：PRD V1.10。交付方式：先打通新流程真实成片，再补齐全部 P0。用户确认的开发顺序取代 V2.1 阶段安排；旧版保存在 archive/开发计划-V2.1.md。

## 目标和业务顺序

七项输入 → 可选本地视频理解 → 写稿 → 内容拆解及确认 → 分段 TTS → 实测时长及配音确认 → 素材需求 → 素材生产与准备 → talkcraft 接入 → 分镜 → 有声预览 → 渲染交付。

固定 Workflow；模型只在节点内生成约定内容，不能改变后继或自行增加付费尝试。默认正面上半身单角度；只有明确制作要求才增加机位。质检问题弹窗提醒并继续，只有用户主动停止才停止后续调度。

## 实施约束

- 复用 Go、React/Mantine、认证和现有任务表，不新增消息队列或通用 Agent 框架。
- 文案拆解不规划画面；TTS 实测且确认后才输出素材需求。F05 不搜索、生产或拼接。
- 人物用同一照片、对应真实声音和自然皮肤要求生成。素材内嵌声音静音，最终旁白整轨只混入一次；不任意变速、循环人物或换声补时长。
- 首套扁平矢量、第二套线条风格来自 mg-styles-15；原提示词、源码快照、提交和许可均留档。其他三个动效参考仓库标记 reference-only，外链和提示词不冒充已发布模板。
- talkcraft 使用实测时间基、语义、SHOTBOOK、同源镜头表、组件、有声预览及逐镜缓存。质量结果与制作完成状态分开。
- 模型提交前保存 submitting，回单立即保存 taskId。查询超时查原单，未知接单禁止盲目重交。关闭浏览器不影响后台；重启后显式查单恢复。
- 节点从首次实现起记录尝试、时间、用量和费用来源；供应商未返回费用时标未知，不虚构零价或币种。
- 运行冻结输入/配置，旧任务继续按旧版本查询；局部修改创建新运行并保留旧版证据。

## 数据和接口

Project 保存 avatar_v2 版本化输入；WorkflowRun 保存用户归属与运行控制；每个实际节点及子任务单独保存 WorkflowStepExecution。提醒与已读独立保存；大工程、映射和素材在服务端目录，数据库保存受控引用和依赖摘要。

前缀 /api/v1/avatar-mvp：catalog；projects 创建/读取/PATCH；projects/{id}/assets；projects/{id}/runs；runs/{id}；confirm、retry、stop、events/{eventId}/read；artifacts/{artifactId}。旧 tasks 查询/视频继续兼容。确认绑定内容版本，运行绑定输入版本及幂等ID；全部检查所有权，媒体支持Range，前端鉴权Blob，不使用URL JWT。

详细节点与恢复契约见 workflow-v22-contract.md。来源清单见 animation-template-sources.json；实现与验证状态见 workflow-v22-acceptance.md。

## 测试与最终验收

按仓库 TDD，优先验证：确认及锁时时序、首镜质检失败仍完成后续、停止/提交竞态、浏览器关闭、租约与重启、原单恢复、未知订单不重交、局修改缓存、字幕/源时间/整轨一次混入、权限与费用去重。

最终三组不同人物/稿件须覆盖上传/不上传、默认/明确多角度、两套风格、两种真实中文声音及三比例；至少一条30–60秒混合成片同时含人物、动画及真实素材。模拟测试、合成音频渲染回归、真实模型调用、人工效果审片分别记录；不互相替代。

## 部署与边界

仅在 avatar-agent 开发，参考目录只读。更新前备份数据库与服务端.env，增量更新本机WSL2 Docker；保留账号、持久卷、素材、模型缓存，禁止down -v。部署后验证登录、历史任务、新流程、媒体权限，再反馈实测IP与端口。

API Key只在WSL服务端。首版不含支付积分、完整编辑器、自动网络素材获取、通用Agent或InfiniteTalk部署。代码和模板许可按来源记录执行，不把非商业授权当商业授权。
