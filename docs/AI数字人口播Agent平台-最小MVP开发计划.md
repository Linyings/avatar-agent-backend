**1. 唯一目标**

用户上传一张人物照片、输入一段现成口播稿，点击生成：Agent 先规划镜头，为各镜头调用 Seedance 2.5 图生视频接口，获得同一人物不同视角的口播片段及匹配的最终人声，再交给 video-talkcraft 的字级对齐、镜头编排、人物合成、动效与 Remotion 渲染链路，得到可预览、下载的口播 MP4。

首轮只接通经过验证的一条人物生成路径。优先使用 Seedance 2.5；若人物生成、视角控制和嘴型均满足要求，InfiniteTalk 不加入默认执行链。若只在口型/配音方面不满足要求，再验证 InfiniteTalk 备选的可行性；它不能自动补齐主模型缺失的多角度能力。保留一个薄的适配接口即可，不同时开发两套生成系统，不实现自动跨模型重试。

MVP 保留 video-talkcraft 的核心制作能力：按语义组织镜头、动效锚定字级时间戳、人物与文字的布局配合、轻运镜与转场、逐帧渲染及必要质量检查。同时由 Seedance 生成人物真实视角变化，例如正面、左前方、右前方。后期裁切放大和 CameraRig 运镜只负责视觉编排，不能替代多角度素材生成。收缩的是风格、卡片数量和编辑界面。

验证三件事：同一参考人物能否生成身份一致、准确读稿且嘴型匹配的多角度素材；video-talkcraft 的分镜和动效是否适合产品；多次模型调用后的整条链路耗时和成本是否可接受。

**2. 严格控制输入输出**

| 项目 | 本次范围 |
| --- | --- |
| 人物 | 一张单人正面或轻微侧脸照片，半身构图优先；全部镜头使用同一参考图和固定人物描述 |
| 文案 | 用户提供中文口播稿；不接主题写稿、网页抓取或资料检索 |
| 声音 | 模型原生生成的对应人声，或模型实际支持的指定 TTS 输入，M0 验证后固定一种方式；不做音色选择界面 |
| 时长 | 首条目标约 15 秒，拆为 3 个语义口播片段；具体单镜时长遵循接口限制，必要时调整验收稿件长度，再验证至 30 秒 |
| 人物生成与嘴型 | 调用 Seedance 2.5 第三方图生视频接口；InfiniteTalk 仅保留为嘴型备选；画面必须与最终人声匹配 |
| 多角度 | 固定 3 个机位：正面中景、左前方约 20–30° 半身、右前方约 20–30° 近景；实际角度以样片验证，首版不用大侧脸与背面 |
| 多镜头 | 首版按 3 个口播镜头分别生成，成片含 3–5 个语义镜头；固定机位模板，不开发镜头编辑器 |
| 成片 | 一种竖屏视觉风格，基于 video-talkcraft 的表驱动镜头与人物素材契约，按分镜引用对应人物片段 |
| 动效 | 限定 3 类已有卡片/组件：开场标题、重点强调、结尾总结；字幕字级锚定，镜头含轻运镜和一种转场 |
| 分镜规划 | 生成素材前做一次受约束的 LLM 调用：按句分稿、分配角度/景别、卡片、关键词和人物布局；素材返回后按实际音频确定时间，不改写口播原文 |
| 音频 | 同一说话人的连续口播；优先验证同一配音分段驱动，或原生人声跨镜头一致性；无背景音乐和音效 |
| 操作 | 提交、查看整体及各镜头状态、预览、下载；失败后手动重试失败步骤，复用已成功片段 |
| 并发 | 同一时间只运行一个制作任务 |

标题由用户输入，可为空。具体输出尺寸在首个样例通过后固定，默认跟随已验证的竖屏风格。成片帧率优先匹配所选模型的输出，经探测确认后统一；不得把原项目 30fps 演示参数直接套到人物素材上。人物素材的原生质量与成片画布分辨率分别记录。

照片不符合所选模型的输入要求、实际发音与稿件不一致、音频超时长、必要服务未配置等情况应明确报错。原生音频路线不依赖 TTS；指定音频路线才检查 TTS 配置。

**5. 最短执行链路**

先按语义规划 3 个口播镜头及对应的稿件片段，每个镜头明确参考人物、机位、景别、动作、环境、时长和动效。M0 必须先区分下面两种音频路径，并只选一种开发；如果指定音频输入确实可用，优先使用 B 来保证跨镜头音色和语速连续：

| 路线 | 前提 | 执行方式 |
| --- | --- | --- |
| A：模型原生音视频 | 能按指定分段稿件生成准确人声、人物与嘴型，且多次调用的音色和语速一致性可接受 | 同一照片 + 分镜提示词 + 本镜稿件 → 各镜音视频 → 检查读稿/音色 → 拼接对应人声、计算镜头偏移 → 字级对齐 → talkcraft 合成 |
| B：指定配音驱动 | 图生视频接口确实支持以用户提供的音频控制口播，并能按镜头保留身份与视角，且效果通过 | 全稿 → 一次 TTS 和对齐 → 按句切出音频及映射 → 同一照片 + 分镜提示词 + 本镜音频 → 各镜人物视频 → talkcraft 合成 |

如果 Seedance 只能生成自然张嘴但无法准确读稿，或跨镜头声音明显换人，就未通过对应路径的验证。不能把生成的声音任意换成另一条 TTS 后仍宣称口型匹配。若多角度画面已可用而口播不达标，备选评估为“Seedance 多角度片段 + 对应最终 TTS → InfiniteTalk video+audio → talkcraft”。需要重新验证身份、角度、动作和嘴型是否保留，不假定接上就一定可用。若人物一致性或多角度本身未通过，InfiniteTalk 不作为已经解决该问题的承诺。

```mermaid
flowchart LR
    A[照片 + 口播稿 + 可选标题] --> B[Go 创建任务]
    B --> C[Agent：按句分镜 / 角度 / 景别 / 提示词]
    C --> D[Seedance 2.5 API：逐镜图生视频]
    C --> E[本镜稿件或已验证的分段配音]
    E --> D
    D --> F[检查各镜头身份 / 视角 / 读稿 / 嘴型]
    F --> J[确认最终人声 / 对齐实际时间 / 映射素材]
    J --> G[talkcraft：镜头编排 / 人物布局 / 字级动效]
    G --> H[talkcraft：Remotion 渲染 / 检查]
    H --> I[MP4 预览与下载]
```

Agent 在本版自动执行素材生成及 talkcraft 制作步骤。一次受约束的 LLM 调用在素材生成前产生按原稿字符范围/句子 ID 引用的分镜，选择固定机位、景别、卡片、布局和关键词，生成各镜提示词。生成前的时长只是预算；素材返回后由程序按最终音频和字级时间戳确定实际镜头边界、关键词触发点及素材偏移，不依赖模型猜测秒数。程序校验原稿完整且无重复、单镜能力限制、镜头覆盖、资源路径和参数。模型不生成可任意执行的 TSX、Shell 或 Python。首条基准片先用人工固定分镜打通，再接自动分镜。

技术组成收缩为：

- Web：一个制作页。
- Go：任务创建、镜头级状态查询、第三方模型任务提交/查询、现有 LLM 调用、单任务执行调度、结果鉴权；TTS 按路线启用。一个成片任务下首版顺序生成 3 个人物片段。
- Python 工具：talkcraft 对齐/检查脚本与媒体参数探测；主路径不需要加载 InfiniteTalk。
- Node 工具：talkcraft 口播工程骨架，加载本次 timing、镜头表、卡片与人物素材，以 Remotion 渲染成片。
- 现有 PostgreSQL：保存项目、任务与步骤状态。
- 本地磁盘：保存本次素材、中间文件和结果。

推荐演示环境：前后端和 talkcraft 对齐/渲染先使用本机或普通开发主机，人物生成调用已验证的服务接口。主路线不自建 GPU 推理环境。只有启用 InfiniteTalk 时才准备远程 Linux GPU，并增加相应文件交换适配。数据库沿用现有 PostgreSQL 部署，不新增另一种数据库。

Go 通过后台执行器调用受控命令，创建接口立即返回 task_id。网页每 2 秒查询一次状态。先不引入 Redis、消息队列、SSE 推送或多套独立微服务。

模型适配契约只需提供 submit、query、fetchResult，以及实际能力描述。submit 接收镜头 ID、同一人物参考图、本镜稿件或音频、受控机位/景别和提示词；只发送供应商实际支持的字段，不虚构“固定人物”或“镜头角度”专用 API 参数。统一产物为本镜人物视频、实际音频、时长、fps、分辨率、音画偏移和供应商任务 ID。保留 provider 字段即可，MVP 不开发模型市场、选择面板或复杂路由。只有选中的适配器必须真正实现，备选不能以伪造成功结果占位。

**7. 后端最小增量**

以下为建议接口，开发时与已有项目/run API 合并，避免重复造表：

| 接口 | 行为 |
| --- | --- |
| POST /api/v1/avatar-mvp/tasks | 接收照片、稿件和标题，创建所属项目/run，返回 task_id |
| GET /api/v1/avatar-mvp/tasks/{id} | 返回任务状态、当前步骤、耗时、错误和结果资源标识 |
| GET /api/v1/avatar-mvp/tasks/{id}/video | 验证所有权后返回可预览、可下载的视频，支持播放器 Range 请求 |
| POST /api/v1/avatar-mvp/tasks/{id}/retry | 人工重试失败步骤；先查已有供应商任务，复用成功镜头，同样执行所有权和单任务限制 |

播放器如何带上认证应在实现时统一：可由前端鉴权下载 Blob 后播放；若流式播放，则使用仅针对该结果资源的短期签名 URL。不要把现有 Bearer JWT 直接拼进视频 URL。

任务只保存必需字段：用户/项目 ID、输入稿件与标题、输入图片路径、provider 与实际模型 ID、音频来源、步骤状态、音频/时间戳/人物视频/分镜/镜头配置/成片路径、开始结束时间、错误信息。每镜头另存 shot_id、原稿范围、角度/景别、提示词、参考图标识、供应商任务 ID、输入音频范围、实际时长、全局起止时间、源素材入出点、音画偏移、状态、尝试记录及可获取的费用。优先复用现有 workflow run/step 及 JSON 元数据，不新增人物库、计价表和模板管理表。

文件目录建议：data/avatar-mvp/{task_id}/，内含 input、audio、timing、avatar/{shot_id}、talkcraft-project、output 子目录。路径由服务端生成，不接受用户指定系统路径。talkcraft-project 需保留可复现的 timing.json、分镜数据、SHOTBOOK.md、各镜素材清单和时间映射、镜头配置及渲染入口；具体文件形态通过适配层与原项目契约对齐。

任务状态最少包括 queued、running、succeeded、failed；服务重启时将失去执行器的旧 running 任务标记为中断，保留供应商任务 ID，允许人工触发查单获取已有结果。本版不做自动续跑。供应商请求超时不等于对方生成失败，已有任务先查询，不直接重复提交付费生成或切换模型。全局单任务限制由后端执行，不能只禁用前端按钮。

**8. 数字人和音画同步的最低实现要求**

1. M0 先确定音频路线。原生路线保留各镜实际生成的人声，验证音色/语速连续后按稿件顺序形成主人声；指定音频路线先生成整段 TTS，再在句间停顿切分本镜输入，保留完整时间映射。
2. talkcraft 对齐与最终合成都消费同一条已确认人声。每个片段分别保留视频/音频时间起点和全局偏移；统一切片、连接与声画偏移，不随意裁切头尾静音。若生成视频改变了指定配音的时长或起点，先验证/纠正映射，不能直接替换音轨。
3. talkcraft 字级时间戳用于字幕、关键词强调、切镜和转场锚点。嘴型由已选择的音视频模型负责；已达标的主模型结果不再经过 InfiniteTalk 重生成。
4. 原生声音必须检查每镜是否完整读出了分配稿件，合起来无漏句/重复，包括数字和专有名词；字幕对齐实际发音，并把读稿差异显式报出，不通过偷偷改字幕掩盖。每镜时长必须在接口限制内，允许按真实语义片段剪辑成片，不用人物循环或重复素材填补缺失口播。
5. Remotion 使用人物视频画面，最终只混入一次已确认人声，避免人物 MP4 内嵌音轨与单独音轨重复播放。不要对已匹配嘴型的画面再换声音。
6. 检查各镜人物视频与配音的开始偏移、总时长和帧率；优先在生成接口固定统一 fps/分辨率，再按 talkcraft 人物素材契约设置成片帧率，依实际 fps 计算切镜和动效帧数。不得任意变速“凑齐”长度，也不把重复帧转换当作已解决帧率适配。
7. 固定风格内允许人物全屏和侧边卡片两种布局，按分镜让出文字空间，避免遮挡嘴部。MVP 保留人物原背景，不引入人像分割。
8. 人物视频为多段素材。渲染镜头必须明确 source_clip、源入点/出点、全局起止时间和音画偏移；同一素材若用于相邻语义镜头，按全局映射继续读取。不同生成镜头可以从自己的片段起点播放，禁止因切换卡片而把同一段口播从头重播。
9. 若后续启用 InfiniteTalk，优先评估各镜人物视频 + 对应最终音频的 video+audio 路线，并重新检查身份、视角和时长；必要的 streaming 帧数按实际长度设置。该部署与验证不计入主路线首版必交付项。

**8.1 video-talkcraft 必须保留的实现点**

| 核心能力 | MVP 适配入口 | 验证方式 |
| --- | --- | --- |
| 字级时间戳 | scripts/timestamps_cpu.py、scripts/make_timing.py、template/motion-systems/timing.ts | 生成 timing.json；关键词在对应发音时触发动效 |
| 语义分镜与镜头表 | SHOTBOOK 约定、template/motion-systems/shots.ts 的表驱动结构 | 自动产生 3–5 镜，覆盖整条声音，镜头配置可检查 |
| 动效卡 | 例如 impact-open-title、highlighter-sweep、chapter-title-card；最终按内容适配 | 实际使用原组件适配后的实现，至少体现开场、强调、总结三类表达 |
| 运镜与转场 | camera.tsx、life.tsx、transitions.tsx 中本次必要部分 | 有轻运镜和一种转场，人物、字幕、强调互相让位 |
| 人物素材接入 | references/host-footage.md 的时长/帧率/安全区约定，扩展为逐镜素材清单 | Seedance 各镜头输出作为人物输入，正确映射源素材与全局时间，跨镜头音画连续 |
| 渲染与检查 | Remotion 工程骨架、render_shots.mjs 及所需依赖、preflight/qa_extract 等 | 完成可复现渲染；检查帧数、素材引用、文字安全区并输出抽样画面 |

原仓库本质是本地 agent skill 和脚本集合，不能假设已有一个可直接调用的 SaaS API。需要薄适配层把用户输入、生成素材和受控分镜写入 talkcraft 工程，再调用渲染。原 shots.ts、演示卡与 scene import 中的样例数据需要替换，不能原样拷贝后直接运行。

本次只适配必要脚本及检查项，明确记录未接入的完整质检规则，不把部分检查通过表述为完整 talkcraft 三重验收全部通过。若使用分镜分段渲染，遵循原脚本的整条音轨一次混入与帧数断言，避免分段音频编码延迟累积。

**8.2 多角度、多镜头的最小实现**

| 环节 | MVP 做法 |
| --- | --- |
| 人物约束 | 每次使用同一原始参考图和固定描述，保持脸部、发型、服装、环境与光照；若接口支持多参考图等能力，验证后再采用，不假定存在 |
| 固定镜头模板 | 开场正面中景 → 讲解左前方半身 → 总结右前方近景；机位角度指相机相对人物的视角，提示词另行约束人物视线与轻微动作 |
| 图生视频请求 | 每个镜头独立请求 Seedance，改变视角/景别并限制动作；不要求模型在一次生成中准确完成全部剪辑 |
| 时长安排 | 按完整句子分配口播，不硬切单词；根据实际 API 最短/最长时长和配音长度选择稿件，生成预算与最终时间分开保存 |
| 身份一致性 | 抽取各镜头首/中/尾帧，人工核对脸、发型、服装及环境；同图/同描述仅是约束，不保证结果，seed 即使可用也不等于身份锁定 |
| 镜头连接 | 优先在句间停顿切换真实机位；说话期间用硬切避免双重嘴部叠影，已有一种转场可放在开头/结尾或非口播卡片处 |
| 失败处理 | 失败或不达标镜头标明原因，手动重试该镜头，保留成功素材及供应商任务记录；不做用户自由编辑与镜头选择 |

至少两个机位必须出现可辨认的人物/环境透视变化，其余镜头也应符合模板的机位/景别，不能用同一正面视频的裁切缩放代替多角度验收。多次生成导致的场景差异可以是计划内切镜，人物换脸、服装突变或音色换人不算通过。

若原始单图无法稳定生成目标视角，M0 明确记录阻塞。补充用户真实多视角参考图或增加生成多视角参考图的模型，属于待决策的后续方案，不在首版静默增加第二套图像生成系统。

**9. 开发顺序与阶段验收**

| 步骤 | 开发内容 | 验收结果 | 估计工作量 |
| --- | --- | --- | --- |
| M0：验证第三方模型 | 核实 Seedance 实际模型 ID、API 权限、图生视频/音频能力、时长；同一参考图试做正面/左前方/右前方三个片段 | 三镜样片及对比帧；确认读稿、嘴型、身份、服装、视角和声音连续性，选定音频路线；记录总调用成本/耗时，口型不达标再评估备选 | 约 1–2 天，API 已可用且试生成结果可接受 |
| M1：talkcraft 基准片 | 固定三镜模板，建立逐镜素材与全局音频映射；适配对齐、3 类卡片、人物布局、运镜/转场 | 一个命令得到约 15 秒真实多角度、多语义镜头成片；接口允许时再到 30 秒，保留可复现工程 | 约 3–4 天 |
| M2：最小 Agent | 生成素材前从原稿规划三镜、角度/景别与提示词，按最终声音确定时间并写入 talkcraft 工程 | 新稿件可以自动调用模型生成三镜，并编排为 3–5 镜成片，不依赖逐条手写代码 | 约 1–2 天 |
| M3：接入后端 | 一个真实模型 API 适配器、各镜任务 ID、提交/查询/下载/手动重试接口、既有认证与持久化状态、串行执行 | HTTP 提交后后台运行，刷新可查每镜状态；重试复用成功镜头，供应商超时不会自动重复生成 | 约 2–3 天 |
| M4：接入页面 | 上传、稿件输入、整体及镜头进度、视频预览、下载和失败重试 | 用户不操作终端即可从照片与稿件获得多角度 talkcraft 风格成片 | 约 1–2 天 |
| M5：样例验收 | 三组完整样例、失败镜头重试、人物/声音一致性、嘴型、字级动效、切镜音画连续性、渲染检查与成本记录 | 三条真实成片、各镜来源与对比帧、对应 talkcraft 工程和效果/耗时报告 | 约 1–2 天 |

M0 约 1–2 个工作日用于验证，模型迭代等待不作固定承诺。第三方 API 可用、M0 验证通过、已有 LLM/必要音频服务可用、复用授权明确后，单名熟悉项目的开发者完成 M1–M5 暂按约 8–13 个工作日规划，并在 M0 后细化。该估计不含接口等待、多轮模型效果调优，也不含 InfiniteTalk 部署。多角度、多片段任务管理新增了工作量，上一版 7–11 天估计不再作为本版承诺。启用备选时另行估计。

优先完成 M0 和 M1，再开发页面；先确认真实效果，避免把时间投入周边模块。

**10. MVP 完成标准**

必须同时满足：

- 至少三组不同人物照片/稿件完成全流程，每组内部保持同一人物，每条有 3 个真实模型生成的人物片段；先验收约 15 秒，接口支持时增加接近 30 秒的样例，并记录实际单镜及整片时长边界。
- 网页操作可以得到可播放、可下载的 MP4，人物、标题、配音、字幕完整。
- 每条视频含 3–5 个语义镜头，实际使用 talkcraft 动效组件、运镜/转场和时间戳机制；人物片段覆盖固定三镜模板，至少两个机位有可辨认的真实透视变化，不能只用裁切缩放模拟多角度。
- 每次生成均保留 timing、分镜、各镜提示词/参考图/供应商任务 ID、素材时间映射、镜头配置与 talkcraft 渲染工程；能追溯每个成片镜头来自哪个模型片段。
- 口播没有漏句、重复音轨和明显截断，字幕基本跟随语音；嘴型、跨镜头身份/服装/声音一致性和切镜连续性通过人工评审，保留对比帧与结论。
- 生成失败不会显示假成功；能指出具体失败镜头以及输入、必要的 TTS、供应商生成、读稿/音画验证、对齐、分镜或渲染步骤；人工重试前可查询已有供应商任务，成功片段无需重复生成。
- 刷新页面可以继续查询正在执行的任务；服务重启造成中断时能明确提示，不永久停留在“生成中”。
- 每条样例有输入、实际供应商和模型 ID、音频来源、逐镜请求配置、输出、阶段耗时及可获取的调用费用记录；整片费用包含各镜及重试调用，而非只记录一次请求。只有自建推理才记录 GPU 型号与显存峰值。本版不做用户计费。

本版不承诺实时生成，也不预设未实测的每条成本。普通媒体检测只能检查可解码性和时长，嘴型与身份质量需要人工确认。

交付物：一个可用制作页、带镜头状态和失败重试的最小任务 API、一个经过验证的 Seedance 2.5 第三方 API 适配器、talkcraft 适配层与可重复运行工程、一次受控分镜规划、固定三机位模板、一个固定风格及 3 类动效组件、环境配置说明、三条多角度演示成片与简短基准报告。InfiniteTalk 的备选接入说明保留，部署和可运行适配器不作为主路线验收条件。

**11. 开发前提与本次不做的准备**

- 主路线先核实 Seedance 2.5 第三方图生视频接口、账号权限、参考人像限制、角度/景别控制、跨请求人物与声音一致性、是否支持准确读稿/指定音频、单镜最短/最长时长及音轨行为；不能仅凭模型名称或提示词推断这些能力。
- 指定音频路线需要可用 TTS；原生音频路线直接使用模型对应声音，首版不强求额外固定某个 TTS 音色。
- 仅在启用 InfiniteTalk 备选后，准备 GPU 和模型权重并验证推理。此前本机 RTX 3050 6GB 用于前后端开发；备选推理建议远程 Linux GPU，具体卡型依实测决定。
- 自动分镜使用一个已配置的 LLM；M1 用固定三镜先验证真实效果，M2 才加入生成素材前的自动分镜/提示词及生成后的时间映射，不增加聊天产品或多 Agent 系统。
- video-talkcraft 的 [随项目保留的许可](../backend/avatar-runtime/TALKCRAFT-LICENSE) 要求商业使用先获作者授权；实际代码/模板复用需确认许可范围。Remotion 与下载权重条款也按实际使用确认。本计划不以“仅做 MVP”为由假定已获商用许可。
- 不购买或部署生产基础设施，不先修完整 SaaS 的全部非核心模块，不发布公网商业服务。

首个成果应当是一条可复现、可以直接观看的数字人口播成片，而不是一个仅有页面和模拟进度的演示。
