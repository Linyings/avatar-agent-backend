# 内容驱动的动效制作（2026-11-08）

风格演示只用于选型。F07 根据当前段落文案、项目主题、制作要求和同段数字人视频帧生成动效方案；正式制作不调用 `renderNative`，不把原演示片或固定图形故事作为成片素材。

## 制作与缓存

- F05 按当前内容规划动效；F07 在 F06 人物素材就绪后采样真实画面。纯动效项目无需人物视频。
- 模型只接收原参考提示词的视觉特征部分，不接收原故事、品牌和整段示例提示词。
- v2 项目中，AI 输出场景、原文引用、主题图形、布局和配色倾向，可信渲染器使用本地 SVG/Three.js 图形逐帧制作，支持 15 种视觉风格。v3 项目另外生成专用 Canvas 绘制源码，由隔离浏览器逐帧执行，详情见 [director-workflow-v3.md](director-workflow-v3.md)。
- 标题和标签必须有当前口播原文依据，数字不改写。过长或改写的标题优先改用同场已选择的原文短标签，不增加模型调用；不修补或猜测虚构数据。
- 动效场景与元素按实际配音字词时间入场。未匹配部分会标记 estimated；不会把后段信息挤到前段时间。
- 缓存包含文案、主题、人物素材、配音、制作要求、风格与相关渲染源码指纹。新逻辑不会命中旧演示片缓存。编码失败后可复用已验证方案。
- 原始案例、提示词和来源许可仍保留在参考下载包内，README 明确区分参考复现与项目生产。

F10/F11/F12 继续安排分镜、人物与动效分层、预览和最终合成。旧成片保留原版本；要应用新逻辑，在“动效制作”节点点击“从此步骤重做”，审核方案后点击“应用修改并重新制作”。

## 验收范围

- Go：原文校验、无关人物过滤、实际帧传入、风格参考隔离、标题修整、渲染重试复用方案、缓存失效及相关工作流测试。
- Runtime：TypeScript 检查、21 项 Node 测试、9 项 Python 测试。
- `verify-content-motion.mjs` 使用明确标记的两组固定方案渲染 15 种风格；校验三种比例的编码、帧数和解码。它不代表真实模型验收。
- 真实联调复制既有项目第一段的数字人视频、配音和时间轴到隔离目录，用实际人物帧调用服务端模型。对已返回结果做本地标题修整后生成新动效，避免为格式修复重复付费。`verify-live-content-motion.mjs` 用现有分层合成组件验证这一段；验收分镜是本地固定分镜，不表示重做了用户整个项目。
- 视觉服务原配置的模型返回 404；通过同服务可用模型清单和实际图片请求验证后，改为当前 Agent 已使用的模型。凭据仍仅在 WSL 服务端配置。

证据保存在 `backend/data/wsl-deployment/content-motion/`（被 Git 忽略）。部署仍使用 `deploy/wsl2/deploy.ps1 -Service all`，保留数据库、素材、模型缓存；部署后用 `verify-current-browser.cjs` 检查真实首页、风格说明、登录及已有工作台。
