# 口播导演工作流 v3

新版采用 `avatar-workflow/3.0`。新项目默认展示 11 个阶段，内部执行步骤保持兼容，以便局部重做与追踪费用。

| 阶段 | 行为 |
| --- | --- |
| 1 用户需求整理 | 保存主题、画幅、人物、风格与参考资料 |
| 2 需求分析 | 区分目标、约束、重点与假设，生成制作需求说明 |
| 3 参考素材分析 | 分析图片、视频采样、TXT/Markdown 与可访问网页，说明未读取范围 |
| 4 导演稿设计 | 先设计全片结构、镜头目的、构图、动效、转场与声音安排 |
| 5 解说文案撰写与确认 | 依据导演稿写口语化文案，用户确认后继续 |
| 6 TTS 配音与时长校准 | 使用实际声音与字词时间更新导演稿，配音确认后制作 |
| 7 镜头与专用动效制作 | 汇总素材规划、人物生成、代码动效、字幕与分镜 |
| 8 镜头审阅与修改 | 每镜生成带声音的融合预览，全部就绪后允许确认 |
| 9 分层融合与逐帧渲染 | 复用已审阅且未变化的镜头帧合成完整视频 |
| 10 成片预览与修订 | 预览完整成片和封面，确认后交付 |
| 11 成片交付 | 交付节点只展示最终视频与封面，中间产物留在对应步骤 |

需求、参考分析、导演稿在节点详情可读和下载。导演稿在文案、配音、分镜变化后校准；预计时间与实测时间区分记录。人物支持圆形头肩小窗及四角位置。当前声音来自已有旁白通道，转场以现有剪切和画面动效为限；尚未新增音乐音效生成、抠像或三维跟踪能力。

整片不设 90 秒或其他累计时长上限，按用户要求与内容信息量规划。实际配音时长用于校准每段起点与全片时间线；只校验配音是否齐全、时长是否有效，不因总时长较长拒绝制作。旧版本因 90 秒限制失败的任务，工作台提供“继续制作”入口，复用已完成配音并进入整批确认。读取项目、刷新页面和更新部署不会自动启动制作。

## 确认与版本

文案、配音、镜头、成片分别确认。镜头/成片确认使用实际内容指纹，缺失预览及重复或过期确认会被拒绝。确认后不重复生成相同视频帧。聊天中的状态卡按出现时的位置保留，交付卡不混入镜头预览。

历史项目继续保持原流程；局部修改不会自动触发全部前期分析。工作台的“使用新版 11 步流程”生成可审阅的重做提案，应用后创建新版，保留历史产物。局部修改沿用内容与素材指纹：未变化的配音、人物与渲染结果可复用；修改参考、人像或导演设计会重新计算相应依赖。

## 专用动效执行

新版动效请求读取当前段落、实际人物帧、风格特征和导演稿，同时输出结构化场景及专用 Canvas 2D 绘制函数体。兼容模型将代码放在各场景的返回结构，本地归一化后复用，无需再次调用模型。文字必须来自当前原文，过长标签自动换行，字幕添加衬底以适配动效背景。场景时间依据配音对齐。旧 v2 动效仍走可信组件渲染器。

代码仅在无同源权限的浏览器 iframe 中执行，设置 CSP、禁止网络和请求拦截，并限制每帧执行时间；不在 Node/Go 进程中执行模型代码。语法检查用于报错，不作为唯一隔离边界。渲染缓存包含源码和关联导演镜头的指纹。

## 验证入口

- Go 测试覆盖前置设计顺序、历史兼容、素材失效、两次新增确认、预览缺失拒绝及确认后不重复渲染。
- 前端测试覆盖 11 阶段聚合、当前节点定位、聊天状态、确认与交付筛选。
- `test-director-runtime.sh` 使用明确标记的固定夹具，检查代码绘制、圆形人物窗、两镜有声预览和渲染缓存。
- `TestDirectorWorkflowLivePlanning` 为可选真实模型联调；服务端凭据通过 WSL 环境传入，已完成的前期分析可保存复用。
- `test-director-live.sh` 使用上述真实模型代码及既有真实人物/配音生成独立样片。验收用固定两镜构图，不表示整个旧项目已重做。
- `verify-director-browser.cjs` 检查实际部署的新项目 11 节点、文案上传及响应式布局，不调用视频生成服务。

验收产物位于被 Git 忽略的 `backend/data/wsl-deployment/director-workflow/`。更新部署使用 `deploy/wsl2/deploy.ps1 -Service all`，保留现有数据库、素材和模型缓存。
