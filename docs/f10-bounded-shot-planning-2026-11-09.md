# F10 分段镜头规划与模型预算

## 处理的问题

2026-11-09 的运行 `74f95998-614c-4cc7-ac9d-e94fcdc74376` 在 F10 失败，供应商返回 HTTP 200、`finish_reason=length`，请求输出预算和实际 completion_tokens 都为 6000。原流程将整片素材、动效源码、导演稿一次发给模型。详见 `f10-shot-diagnosis-2026-11-09.md`。

本次不通过流式传输规避输出上限，也不假定模型别名代表某个已核实的最大窗口；改为缩小单次工作量，再由程序合并。

## 实现

- F10 按配音段落规划，每个窗口不超过 20 秒；长段落自动分窗。每窗通常最多 4 镜，全片仍遵守原有 160 镜限制，窗口多时提前分配更小的镜头数预算。
- 发给模型的是当前段落、相关导演镜头、全片摘要、制作要求、素材类型/时长/内容摘要及动效语义。顶层和场景级 Canvas 源码、路径、音频文件名和缓存指纹均不发送。摘要字段有长度上限，用户制作要求保留完整；过大的要求明确报错，不静默裁掉。
- 单批 JSON 数据最多 16000 UTF-8 字节，包含系统提示词及契约预留后的模型文本输入最多 24000 字节。所有批次先预检，再允许任何模型提交。
- 模型返回段落内时间；程序生成稳定镜头 ID、转换全片时间并校准人物源入点，再检查素材范围、连续覆盖、叠加、布局、数量和解释长度。最后本地合并和全片校验。
- 子步骤为 `F10/batch-001` 等，各自保存提示词、输入、进度、用量和错误。画布汇总节点展示当前分段及完成数量。
- 每段结果分别写入运行目录的 `shot-plans/`，原始成功响应仍写入 `model-results/`。缓存缺失或损坏时可用已保存响应恢复；两份成功结果都不可用时明确停止，不重复提交。输入、素材身份、相关导演内容、提示词、配置或输出预算变化会使对应缓存失效。
- 已完成但输出截断的分段可由用户重试；此前成功分段复用。不自动重复提交截断请求。提交状态未知时保留查单限制。
- 旧 F10 模型费用保存在原 Orders/Attempts 中；新的 F10 父步骤只负责本地汇总，不把旧 6000 tokens 算成新一次调用。

## 后续步骤与公共预算

F11 镜头预览、F11.1 渲染、F11.2 成片检查、F12 交付均为本地处理；保留镜头审批和成片审批。旧版 F12 也保持本地渲染。回归测试禁止这些阶段新增模型调用。

工作流提交入口和 AvatarContent 供应商入口都检查文本输入预算。预算拒绝发生在提交前；供应商适配器明确拒绝尚未发送的请求时，不留下未知付费订单。

可在 WSL 服务端 `/opt/aicat/avatar-mvp/.env` 配置以下非敏感限制，然后更新服务：

| 变量 | 默认值 | 有效范围与含义 |
| --- | --- | --- |
| `AVATAR_SHOT_MAX_TOKENS` | 6000 | F10 单窗输出预算，1024–32768 |
| `AVATAR_MOTION_MAX_TOKENS` | 12000 | 保留已有单场景代码预算，4096–32768 |
| `AVATAR_MODEL_MAX_OUTPUT_TOKENS` | 32768 | 应用级输出封顶，256–32768；实际请求取步骤预算与此值较小者 |
| `AVATAR_CONTENT_MAX_INPUT_BYTES` | 131072 | 普通文本输入预算，4096–1048576；F10 另取 24000 字节较小者 |

未设置、无效或超出范围的值使用默认值。普通内容步骤默认输出仍为 6000 tokens。上述数字是应用防线，**不是供应商模型能力声明**；应按实际接入服务支持值配置输出封顶。UTF-8 字节检查不是精确 tokenizer，不涵盖图像 token；保留原供应商返回的用量和截断诊断。分段降低风险，不保证所有模型在任意配置下都不会截断。
