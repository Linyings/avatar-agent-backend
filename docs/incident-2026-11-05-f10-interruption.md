# 2026-11-05 F10 中断与安全恢复

## 已确认原因（北京时间）

- 运行 `8ef449c3-99a1-41a2-b94c-8b5b0b4e5bf7` 在 18:05:38 进入 F10 分镜请求。
- 上一次仓库拆分部署在 18:06:06 重建 API。部署前仅确认媒体子进程结束，漏掉了仍在等待远端模型响应的工作流。这次部署检查不充分是该任务中断的直接原因。
- 任务恢复检查将运行标为 `interrupted`；F10 留下 `submitting`、无供应商订单号、无保存返回。用户重试得到 HTTP 409，是防重复付费保护，不是前端按钮失效。
- 配音、人物视频、动画素材仍然完整。不能据此认定原 F10 请求未计费，也不能清空提交状态后重发。

## 修复

- 仅在用户明确重试时，为 F10 提供本地恢复：优先读取保存的返回，否则根据已有素材和锁定配音时长生成保守分镜。检查 F09 完成、声音已确认、素材文件存在、分镜区间合法。
- 原请求的提交状态、订单及未知费用保留；本地重试不创建新供应商订单。其他未知请求继续阻止重复提交。
- 后续本地渲染失败仍可重试，不被历史 F10 未知账单永久阻塞。恢复分镜失效时拒绝执行，不回退到付费模型调用。
- 部署脚本在重建 API 前取得与任务准入相同的 PostgreSQL advisory lock (`744834291`)，检查旧版/新版主任务记录；运行中的远端请求同样阻止重建。锁覆盖 API 容器替换，消除“检查空闲后新任务刚好启动”的竞态。API 启动恢复也需要该锁，所以健康等待在释放后使用 `--no-recreate` 执行，禁止在锁内 `--wait`。
- 全量部署不在此锁内重建现有 PostgreSQL；数据库配置升级应单独安排维护。部署之间另有文件锁。
