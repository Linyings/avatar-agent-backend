# 第 7 步素材规划失败与重试循环

## 现象与证据

项目 `465168c3-7348-4914-b535-b59d9f0d7d16` 在第 7 个展示步骤内的 F05 素材需求规划失败，F06 人物视频、F07 动效制作尚未调用。两次历史文本请求均收到 HTTP 200，但返回内容不是有效 JSON，错误码为 `model_invalid_json`。

最新失败运行：`67bbb107-8bb6-4a48-a206-46131cde50a2`。此前运行：`672a319a-9453-4b82-88e8-be114cf080e0`。点击重试实际创建了新的尝试，并非按钮没有提交；同样的整片规划请求再次失败。

旧实现没有保留失败响应正文、结束原因和 token 用量，因此不能从旧日志断言截断。对该运行保存的内容进行隔离复现，得到 HTTP 200、`finish_reason=length`、`completion_tokens=6000`；正文从 JSON 对象开始，但字符串在中途结束，解析报 `Unterminated string`。复现使用相同已保存输入和规划规则重建请求，并非历史请求的字节级回放。

三项原因叠加：

1. 整片 7 段的详细素材需求一次生成，共用 6000 token 输出预算，复现中输出被截断。
2. 已收到但格式无效的文本结果被归类为提交状态未知，混同于网络中断。
3. 测试模式下页面隐藏具体错误，只显示“上次请求未完成，可以重试”。

本次与磁盘空间、成片时长上限无关。7 段音频累计 93.537249 秒；无成片 90 秒限制。

## 修复

- F05 每批最多规划 2 段，携带全片主线、相关导演场景和原制作约束。输出仅含本批素材需求，避免复述完整导演稿。片长不决定是否允许制作。
- 每批结果先校验并持久保存，成功批次可在同一运行的显式重试中复用。全部合并后再校验段落覆盖、时长、素材、动效及全片机位要求，统一需求 ID；部分结果不会进入视频制作。
- 缓存写入前校验上传视频的已理解源区间；最后一批必须补齐尚未覆盖的指定机位和显式启用的素材种类。错误结果不会作为成功批次缓存，显式重试可以替换失败批次，防止遗漏要求的规划被反复复用。
- 工作流结构化文本请求统一发送 JSON 返回格式约束，保留动效代码请求独立的代码权限范围。
- 即便截断结果恰好是有效 JSON，只要供应商报告 `length` 也视为不完整结果。已返回内容的格式错误记录为 `completed` 提交与 `model_output` 失败；网络和供应商响应封装异常继续保留未知状态，不自动重复请求。
- 失败日志保留固定结束原因、用量及请求 ID，不记录凭据、请求正文或上游原始错误。
- 历史 F05 `model_invalid_json` 在页面明确显示“素材规划返回格式异常”，提示视频和动效尚未开始、已有配音保留。其他故障展示实际错误，不再统一吞成泛化提示。
