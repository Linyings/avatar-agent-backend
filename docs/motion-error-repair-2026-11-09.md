## 修改后的行为

1. 每个动效方案/场景允许首次执行后最多 3 次自动修复。只处理已收到结果的模型输出错误、确定的动效校验错误，以及明确拒绝的 429/5xx；未知订单、鉴权、输入超限和本地环境失败不自动重复生成。
2. 每次修复包含最新后台错误、修复要求和有大小限制的上一份输出。重试次数、原因和各次失败记录写入工作流状态，刷新或恢复进程不重置次数。三次均失败后停止，显示“等待你处理”。“交给 Agent 排查”仅请求读取错误和提供方案，不自动启动第四次生成。用户明确选择重试后只执行一次错误驱动的修复，不再开启一轮自动重试。
3. 所有经 `w.model` 执行的后续模型步骤在手动重试时也带上原错误。Agent 先 inspect 当前失败步骤，再调用一次恢复工具；工具不通过重复调用绕过重试上限。
4. 同一运行中已有场景代码先用新规则重新检查，能够通过时直接复用。只修复失败场景；完整成功的视频、场景方案与其他成功场景保持可复用。缓存按节点隔离。
5. 用与渲染器相同的字词时间对齐计算每场真实时长，再交给代码模型。提供 `duration`、`hold_seconds`、元素的 `local_at` 与 `enter_at`，明确区分素材时间和场景局部时间。
6. 编码前在隔离 Canvas 中按真实帧时间运行场景。关键标签必须在同一帧完整出现且保留连续阅读时间，不能跨帧拼凑。宽泛标题不能替代独立的关键标签。数字及单位可与名称分开排版，错误数值或遗漏单位仍被拦截。
7. 语法检查解析局部作用域，允许合法局部变量 `top`；未声明的浏览器全局、网络、动态执行和 Canvas 越界访问仍受原隔离规则约束。
8. 媒体子进程输出结构化诊断，前端展示实际原因、自动重试次数、修复策略和历史错误。用完三次自动机会后主入口改为“交给 Agent 排查”；视频节点保留手动修改提示词、AI 改写和重新生成入口，增加“调整或跳过此步骤”。AI 改写会读取该视频的失败原因、已有修复要求和最近错误记录，仅保存可检查的草稿。
9. 跳过通过 `avatar_edit_node.skip_need_ids` 生成修改提案，确认后才生效。要求剩余素材符合项目需求，且存在完整覆盖受影响段落的已就绪替代画面；素材缺失、只覆盖部分配音或删除全部必需动效会被拦截。新版本移除被跳过的需求并重新规划镜头，原版本保留。
