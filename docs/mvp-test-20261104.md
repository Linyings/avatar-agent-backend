**发现的实现问题及修复：**首镜配音 2.48 秒，旧代码取整后传 `duration=3`。[RunningHub 当前模型文档](https://www.runninghub.cn/runninghub-api-doc-cn/api-498749503) 明确枚举 `-1` 或 `4–30` 秒，3 秒不是合法值。已先添加会失败的回归测试，再将该模型的短请求提升至至少 4 秒；保留最终配音、字幕时间轴和素材入出点，不变速、不补重复人物片段，也没有改变其他供应商时长规则。

此问题可能解释本次提交失败，但**原供应商响应未被保存，不能将推测当成明确拒单证据**。当前任务保持 `unknown`，不会在修复后自动再次提交或伪造订单号。需供应商确认原请求的接单状态后，才能决定查单恢复或另行提交；本次没有追加第二次视频请求。

修复已部署到本机 WSL2 Docker，Go avatar/config/server 定向测试通过；最终 API、Web、PostgreSQL 均 healthy，登录和配置接口再次验证通过。API 更新重启后，新任务仍保留同一 ID 与 `unknown` 提交状态，没有自动重发。容器内一次性授权配置为空，基准人工验收开关仍为 false。

一次性授权采用服务端 `AVATAR_MVP_BASELINE_REQUEST_ID` 精确匹配；数据库事务锁与持久任务标记防止重复消耗。其他请求仍受原基准门禁限制，正常幂等请求返回原任务。相关测试覆盖错误请求、授权消耗后重复使用、切换模型后复用授权以及旧记录保留。测试后已从 WSL `.env` 移除已消耗的授权，`AVATAR_MVP_BASELINE_APPROVED=false` 保持不变。
