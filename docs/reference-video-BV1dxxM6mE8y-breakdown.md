# 混合型数字人口播视频：参考拆解与导演方案

分析日期：2026-11-04。

参考视频：[《AI群像戏视频用这三招就够啦》](https://www.bilibili.com/video/BV1dxxM6mE8y/)，作者：李一帆AIGC，时长约 3 分 58 秒。

本报告基于网页信息与开场、讲解、操作演示、案例和后段的关键画面抽样。时间点用于定位画面，不代表精确切镜边界；没有取得作者工程、原始素材或完整音轨分析。声音设计、拍摄设备、软件选择与制作顺序属于建议方案，不能认定为作者实际做法。人物是否实拍、是否数字人也不能只凭外观确认。

## 一、先区分两层作品

这条视频内展示了 AI 多人物剧情片，但外层作品本身是“人物讲解＋案例引用＋软件演示＋图文包装”的教程视频。当前平台要学习的是外层的编排能力，无须先实现视频内介绍的全部群像戏或 3D 导演台能力。

核心是：每句话需要怎样的视觉说明，再决定调用哪种素材生产方式。数字人生成只是人物素材的一条生产分支。

## 三、如何生产这些画面

### 1. 人物主讲与圆形画中画

真人路线可以使用固定机位拍摄：人物中景、稳定曝光和白平衡、柔和主光、背景与人物分开、单独清晰收音，按完整段落录制并留出句间余量。固定中景可适度裁成近景，真正侧面视角需要另一机位或另拍素材。

数字人路线先确定人物参考、服装、背景、音色和表演要求，再用确定的台词音频生成需要露口型的片段。视频模型是否能保留指定台词、声音与嘴型，应以实际结果判断。InfiniteTalk 仍是音频驱动人物的备选，不必与每次视频生成串联。

同一条人物素材可以全屏展示，也可以通过圆形遮罩变成小窗。圆形小窗不等于抠像：保留圆形范围内的原背景即可；只有把人物独立放到其他背景时才需要分割或绿幕。

只做缩放、平移和裁切不会产生真实新机位。多角度应服务叙事，不能机械地每条视频都轮换三个角度。

### 2. 补充画面：网上素材、录屏与 AI 案例

素材按用途选择：具体事件需要相关证据或引用；软件教学需要真实界面录屏；抽象概念适合示意图和动画；没有现成画面的情境可以生成。

录屏先按讲解步骤录出完整操作，再剪掉等待、错误与无关移动，对关键控件局部放大。观众要看得清操作目标，不能只看到快速移动的界面。

网络素材应记录来源、可用范围、原片入出点、引用说明和对应台词。搜索结果只是候选，需要人工或工具确认内容确实支持该句话；不应以“画面好看”替代语义相关性。

### 3. 字幕、图解与动效

普通字幕承担听读辅助；关键词承担强调；卡片和关系图承担解释。三者不应重复占满画面。

圆形小窗、圆角素材容器、边框、背景虚化、标题、指示线、局部放大等都可以用 Remotion/React/SVG/Canvas 实现；复杂特效也可先做成独立素材再合成。剪辑软件同样能制作这些效果，不能由成片反推作者用了哪款工具。

动效应绑定“话说到哪里”：说“第一步”时亮起步骤，说“前后对比”时出现对照，说到按钮时才圈出按钮。不要随机选一个动画填满整段。

### 4. 声音与剪辑

建议用连续主讲音轨串起整片。画面从人物切到案例，旁白继续；展示案例原声时，先为原声预留明确区间，避免两段人声争抢。

背景音乐在人声出现时降低，点击、强调和转场音效少量使用，最后检查响度、爆音与句尾截断。这是推荐的制作方法，本次未对参考片做完整声音测量。

人物画面必须与其所用音频对应。补充画面不涉及人物嘴型，可以自由安排视觉节奏；不要为了补画面长度随意变速人物、替换声音或循环说话片段。

## 四、导演方案应写什么

导演方案应同时交代“观众理解什么、听到什么、看到什么，以及为什么这样呈现”。一份可执行方案至少包含：

1. **任务简报**：受众、主题、观看后获得的结果、时长、横竖屏、发布渠道。
2. **内容结构**：结果或问题开场 → 解释原因 → 方法分步 → 实例证明 → 结尾归纳。
3. **视觉规范**：人物、背景、色板、字体、字幕、画中画位置、素材容器、图解样式。
4. **音画分镜表**：每个语义段的台词、画面类型、素材、景别、动效、声音与切换理由。
5. **素材任务单**：现有素材、需检索素材、需录屏内容、需生成镜头、失败时的替代画面。
6. **时间线规则**：音频主轴、镜头入出点、人物与驱动音轨映射、字幕和强调词的触发时间。
7. **验收与生产记录**：信息准确、可读性、人物身份和嘴型、黑帧/卡顿、素材来源、步骤耗时与费用。

先做语义分镜和大致时长；确定配音后再按实测时间锁定分镜。提示词是某个生成任务的输入，不能代替整份导演方案。

## 五、一个 60 秒导演方案示例

以下为新创作示例，主题“AI 视频人物为什么一切镜就变脸”，不是参考片逐字转录。时间是节奏占位，最终以录音或 TTS 实测长度调整。

创作目标：让初学者理解人物连续性来自参考约束与分镜规划。风格：固定人物、简洁深色图解、统一强调色；字幕不遮脸或重要控件。

| 时间预算 | 解说意图 | 主画面与人物布局 | 制作任务与动效 |
|---|---|---|---|
| 0–5 秒 | 提问：“为什么同一个人，换个镜头就变脸？” | 两镜前后对比，人物暂不露出 | 使用自有或新生成的演示片段，定格圈出差异 |
| 5–11 秒 | 给出判断：“问题往往出在前面的规划。” | 数字人全屏中景 | 生成这一段对应口播，单个关键词强调 |
| 11–21 秒 | 方法一：锁定人物参考 | 人物参考图为主，讲解者圆形小窗 | 展示服装、发型、外观描述卡，逐项高亮 |
| 21–32 秒 | 方法二：先规划机位和场景关系 | 三格机位示意为主 | 用代码图解正面/左前方/右前方，解释区别；可不生成三个视频 |
| 32–44 秒 | 方法三：带参考执行并查看结果 | 工具操作录屏，必要时保留人物小窗 | 展示图片上传、参数与任务结果，局部放大关键项 |
| 44–54 秒 | 展示同人物的多镜头结果 | 案例全屏，讲解者隐藏 | 合理切换实际案例，旁白继续；不叠加无关卡片 |
| 54–60 秒 | 回收结论：“先锁人物，再排镜头，最后生成。” | 数字人回到全屏，三条结论简短出现 | 对应口播与总结卡，轻收尾 |

人物小窗也是说话视频，必须对应相同时间的配音，不能使用无关循环。若小窗没有解释价值，应隐藏，而不是为了持续出镜而增加生成成本。

## 六、可执行的制作流程

```text
主题与资料核实
    ↓
口播稿＋语义分镜草案＋视觉规范
    ↓
录制/生成配音 → 字级或词级对齐 → 锁定语义时间段
    ↓
素材任务单与预算
    ├─ 人物：实拍或音频驱动数字人
    ├─ 证据：查找、核实、下载允许使用的素材
    ├─ 演示：录屏、截图、操作片段
    └─ 解释：图解、卡片、代码动画
    ↓
占位粗剪：确认内容、画面对应与节奏
    ↓
替换正式素材、精剪与动效 → 字幕 → 混音
    ↓
完整审片与必要修正 → MP4＋字幕＋来源和成本耗时报告
```

先用静态图、代理素材和低分辨率预览确认结构，再生成昂贵镜头和高质量成片。稳定的解说稿与驱动音频要在付费人物生成前确定；后期改词会影响字幕、人物口型和下游时间线。

画面切换按语义和阅读时间决定。可以用每几秒有一次有意义的视觉变化作为初剪参考，但不把固定频率当强制指标；完整操作或有价值的表演可以停留更久。

## 七、对当前 Avatar Agent 的落地建议

当前项目以照片、配音、三角度人物片段与 talkcraft 合成为主。根据项目 README，真实最终成片验收仍有未完成项；本次分析不表示现有 MVP 已具备上述全部能力。

建议先保留现有人物生成分支，把输入分镜从“三个必选人物角度”扩展为按语义选择的镜头类型：

- `presenter`：人物全屏或画中画；记录人物源片段与驱动音轨时间。
- `footage`：现有视频、用户提供视频或已核实的可用素材。
- `screen_demo`：软件界面录屏或截图演示。
- `graphic`：代码图解、比较、关系、步骤和数据画面。
- `case_result`：连续展示方法结果，控制字幕和装饰的干扰。

统一镜头记录应包括：引用的原稿句子、全局起止时间、主画面类型、素材路径及源片入出点、人物布局、文字/动效事件和音频策略。以这份数据驱动合成，模型供应商的变化只影响素材生产分支。

最小扩展顺序：

1. 先完成现有核心链路的真实成片验证。
2. 增加人工上传补充视频/截图，以及人物全屏与圆形画中画切换；不必同时建设搜索引擎或完整素材库。
3. 增加受约束的语义分镜与三到五类常用解释动效，以 30–60 秒样片验证。
4. 再增加候选素材检索、来源管理与相关性核实，逐步减少人工工作。

成本和时间按任务事件记录：开始/结束、墙钟耗时、供应商任务 ID、模型用量、可获得的真实费用、失败/重试与复用情况。供应商未提供价格或账单时标记“待核实”，不要把估算写成实付。人物生成按可见区间计算需求；隐藏人物的图解/案例段仅保留旁白即可。
