# 动态流程与执行反馈修复（2026-11-07）

## 现场诊断

对用户项目 `5daa1faa-a31d-428d-8eaa-521d0eca73d5` 的只读诊断显示：输入仅有人物照片，没有参考视频；`run=null`、`proposal=null`。最后一条 Agent 回复停留在“先把需求参数保存下来”，实际没有提交制作任务。旧画布将所有已安装节点固定列出，因而错误展示了 F01.4 等不适用分支。

## 变更

- 服务端生成 `workflow_plan`：只有选用视频时显示 F01.4；根据人物/动效选择和 F05 的实际素材需求决定 F06、F07、F08。隐藏分支后重连依赖，不留下断链。
- 新项目纯人物口播默认不加入动效，显式 `use_animation=false` 会阻止 F05 额外规划动效。保留旧项目未设置该字段的含义及旧运行缓存指纹。
- 用户要求实际执行时，Agent 不能只承诺“马上开始”就正常结束；最多补充两次继续执行提示。仍未提交则明确返回“尚未启动”。读取旧完成、失败或暂停任务不等于完成新执行要求。
- 工作台和聊天区持续显示真实状态、完成步骤数、当前节点、运行时间和下一步操作，区分未启动、Agent 处理中、后台执行、等待审核、暂停、停止、异常、完成。
- 在数据库状态提交后发布 SSE，前端以 5 秒轮询兜底；刷新后恢复工作流和当前 Agent 活动。Agent 活动保存在服务进程内，服务重启后以持久化任务状态为准。
- 保留文案、配音和修改方案的用户确认操作，不自动批准。
