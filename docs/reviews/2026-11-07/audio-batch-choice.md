# 配音整批确认与运行控制修复

## 原因

项目 `5daa1faa-a31d-428d-8eaa-521d0eca73d5` 的当前运行 `5816b968-dec1-4ed3-9557-e9682d4ae9df` 已完成 p1、p2、p3 的配音。运行状态为 `awaiting_confirmation`，确认项为 `audio`。Agent 在用户说“继续”后误调用了 `avatar.control/retry`，此前重试接口只接受失败、中断或请求状态不明，因此返回“当前运行无需重试”。这是控制动作与状态不匹配，不是配音模型再次失败。

原工作流已经在循环中连续处理所有配音段落，然后才进入一次配音确认。旧状态保留最后一个子步骤 `F04/p3`，加上不明确的确认文案，容易被理解成每段都需确认。

## 修改

- 等待确认时收到重试或继续控制请求，返回正常的当前状态和用户选择说明，不重新生成音频，不直接批准内容。
- 活动运行的重复控制请求也只返回状态；控制期间状态发生变化时重新读取，避免把完成竞态显示为调用失败。
- 新运行整批配音结束时将阶段标记为 F04，界面显示完成段数。制作中明确提示所有段落连续执行。
- 配音完成后统一显示“查看并试听配音”和“直接继续制作”。前者允许试听后确认，后者由用户点击后提交当前版本的整批确认，继续下游制作。
- 文案仍须查看后确认。未完成的配音批次在前后端均不能继续。
- 在等待确认时输入简单的“继续”，工作台直接展示选择说明并聚焦卡片，清除上次临时工具提示，不把指令误送成重试。
- Agent 指引按真实状态区分继续、重试和待确认，明确不要求逐段试听，也不能编造“不试听导致口型错位”等原因。
