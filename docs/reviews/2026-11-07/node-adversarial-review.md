## 发现与修复

| 编号 | 级别 | 触发与影响 | 修复 |
| --- | --- | --- | --- |
| N1 | P1 | 确认方案在事务外读取基础产物、检查指纹；进入创建运行的临界区之前，其他工作流操作改变了基础产物，旧方案仍可创建新运行，覆盖用户刚更新的内容。 | 在运行创建事务内重新读取最新运行、检查方案 ID、版本、基础运行 ID、产物指纹和状态；同时锁定项目行。幂等重放仍先返回已接纳的原运行。 |
| N2 | P1 | 仅从 F10 等下游步骤重做时，项目缓存被清理，即使历史运行的素材文件仍存在，也会再次进入素材生成。共用该路径的人物生成可能因此产生额外调用。 | 输入指纹匹配且不在显式重做范围时，优先复制历史运行中的实际素材，保留素材元数据和质量提示；支持旧版无 `BaseFingerprint` 的记录。显式重做仍使用独立缓存标识。 |
| N3 | P2 | F03 重新分段保留了已清理的口播正文，却清空此前从原稿提取的制作要求与机位；新一轮分段无法从纯正文恢复它们。 | F03 保留已提取的制作要求和机位；从 F02 或更早重新写稿时仍清理它们。 |
| N4 | P2 | 更换默认视觉模型配置后修订 F01.4 解读，继承逻辑不再复制旧解读，随后应用编辑时没有目标，用户修订静默丢失。 | 对源文件未改变的明确人工修订保留已有解读和已完成分析记录，更新其复用标识，防止后续分析覆盖修订。源文件变更仍拒绝沿用旧编辑基础。 |
| N5 | P2 | `#zzzzzz` 等无效字幕颜色符合字符串长度要求，会被保存成待执行方案，但渲染无法显示用户要求的颜色。 | 服务端统一校验非空字幕颜色为 `#RRGGBB`；错误在保存方案前返回，不创建新运行。空值仍可恢复默认颜色。 |

主要实现文件：`backend/internal/server/avatar_workflow.go`、`agent_package_edits.go`、`agent_packages.go`、`avatar_workflow_revision.go`、`avatar_workflow_execute.go`、`avatar_workflow_catalog.go`。
