# 已完成项目的节点编辑与重做修复

## 事故与原因

2026-11-07 14:18（Asia/Shanghai），项目中的请求是：“当前这个项目，我想从第4步‘分段配音’这个步骤开始，把后面的步骤全部重新执行一下”。只读检查持久聊天历史可确认，Agent 的回复记录了先传工具名、再被本轮一次限制拦截的情况。持久历史没有保存这两次调用的完整参数，因此不将回复中的描述当成原始工具日志。

代码确认了三个问题：

- package 注册覆写了通用 `plan_project`，丢失 `rerunFrom`，且 target 没有节点枚举和含义说明。
- 节点参数在 Execute 中校验，失败已经占用 Once。纠正参数后无法继续。
- 原有新运行继承与缓存会复用已完成产物，缺少“明确从此节点全部重做”的失效标记。仅接受节点名不能解决这个问题。

## 最终行为

- `plan_project` 明确区分终点 `target` 与重做起点 `rerunFrom`，兼容已注册 package ID、工具名、中文节点名和 `f4` 等编号格式。F01 定向到需求编辑，不会自动触发生成。
- 参数预检失败不占用 Once；明确返回未提交的结果也允许同轮纠正。成功提交或生成待确认方案仍受 Once 限制，执行错误不会自动解锁重付费。
- `avatar.rerun` / `avatar_rerun` 生成持久重做方案，确认后以新运行执行。起点及以后失效，终点限制本次执行范围。原运行及订单保留。
- 强制重做配音和素材使用新运行的缓存标识，同一运行重试仍幂等；后续无关编辑可复用这次重做后的素材。
- 已完成版本的普通“执行到”返回现有状态，并提示明确重做。不会悄悄创建复用旧产物的新运行。
- `avatar.edit-node` / `avatar_edit_node` 补齐节点内容修改，先生成可确认方案；照片和文件路径仍由受控上传入口管理。
- 改稿、重新分段后清除失效的字幕绑定，并与草稿版本一并保存；未改变的段落保留字幕修订。复用的已确认分段在画布中显示完成。
- 保留原有未知订单阻断、所有权校验、版本/产物指纹校验、稿件及配音审核。

| 节点 | 编辑方式 |
| --- | --- |
| F01 | `avatar_configure` 保存制作需求 |
| F01.4 | `avatar_edit_node` 修订已有源区间解读 |
| F02 | `avatar_edit_node` 替换完整口播稿；`edit_script` 修改指定段落 |
| F03 | `avatar_edit_node` 替换完整分段，允许拆分/合并，必须覆盖原稿 |
| F04 | `edit_voice` 调整音色、选择重配音段落 |
| F05–F08 | 修改素材规划、人物提示词、动效文字、实拍源片段；分支节点校验素材类型 |
| F09 | 修改字幕，保持与既有字级时间戳相同的朗读字数；改解说内容走文案编辑 |
| F10 | 修改现有分镜内容、素材与布局，校验时长和真实素材范围 |
| F11–F12 | 修改分镜、字幕颜色/大小、人物位置，再输出预览和成片 |

工作台节点详情新增“从此步骤重做”和“让 Agent 编辑此节点”。重做按钮先生成方案，点击确认才执行。编辑按钮在输入框填入明确节点编号、名称与内容类型，由用户补充修改要求。
