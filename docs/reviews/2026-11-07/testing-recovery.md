# 测试阶段恢复机制

用户要求优先验证制作功能，暂不以扣费核对和积分统计阻断旧项目继续执行。本次增加服务端 `AVATAR_WORKFLOW_TEST_MODE` 开关，默认关闭，本机测试部署开启。

## 行为

- 旧运行的请求状态不明时，工作台显示“重新执行并继续”；用户明确要求 Agent 继续时可调用恢复工具。
- 无任务号的未知请求可以新建恢复运行，使用当前草稿、模型默认音色和配置，并继承可复用的已确认文案和产物。原运行保留。
- 已有未完成任务号时继续原任务查询；混合步骤中仅释放没有任务号的未知请求，旧尝试保存在订单历史里。
- 同一个恢复请求持久去重，新建恢复和原地恢复均不因重放而重复执行。
- 已经运行中的任务不能再次启动。读取状态、刷新页面、部署都不会自动恢复。
- 文案、配音的内容确认继续保留；本次不实现积分扣减、结算，也不把真实模型错误显示成成功。

## 实际供应商故障

针对当前请求做一次最小连通诊断，返回 HTTP 200、错误码 `1007`、空任务号，错误为 `field 'english_normalization' is required, can not be empty`。返回体 238 字节；未输出凭据或保存未经清理的响应。

官方接口页面 `https://rhtv.runninghub.cn/runninghub-api-doc-cn/api-448183268` 的请求示例和 schema 均包含 `english_normalization`。原适配器遗漏此必填布尔字段，且将明确的参数拒绝当成未知提交。

修复：显式发送 `english_normalization: false`；仅将无任务号且错误码为 `1007` 的明确校验失败归类为 rejected。未知错误、损坏响应、缺少任务号仍保留 unknown；不向界面透传上游任意错误文本。界面可显示安全的参数校验错误码。

相关回归 48 项通过，随后 avatar 包全量 51 项通过；覆盖必填 false 值不被省略、数值和字符串错误码、未知错误保守分类、敏感内容不泄漏。
