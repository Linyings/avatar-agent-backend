# 项目文件与部署缓存清理

项目列表删除成功后，后端同步清理该项目的原始上传素材、项目缓存、全部运行的过程文件和成片，以及旧版运行目录。没有运行记录的项目也会清理上传文件。对话、项目工作流及上传记录同步删除，待结算的积分预留释放，财务流水保留。

删除与上传、任务启动共用互斥保护。正在制作或尚未收尾的项目返回 409，先停止制作后再删除。清理失败返回错误，项目仍保留在列表中，可以重试；不会先隐藏项目再忽略磁盘清理错误。路径由服务器的 UUID 和数据根目录生成，拒绝通过符号链接父目录删除外部文件。

所有前端删除入口通过 ProjectService 清理当前浏览器的 OPFS 素材和 IndexedDB 音频、预览缓存。服务器拒绝删除时保留浏览器缓存。浏览器存储不可用时会记录警告，服务器删除仍已完成；其他浏览器里的离线副本不受服务器直接控制。

媒体处理命令使用独立的临时目录，正常完成和失败退出时都会删除。它位于任务公开素材目录之外，避免渲染打包复制临时目录自身。崩溃后遗留且超过 24 小时的临时目录在下次部署清理。

## 运维入口

在 Ubuntu-24.04 内执行；脚本默认只扫描，增加 `--apply` 才执行：

```bash
python3 /mnt/d/pro/ai_cat/avatar-agent/deploy/wsl2/storage-maintenance.py
python3 /mnt/d/pro/ai_cat/avatar-agent/deploy/wsl2/storage-maintenance.py --apply
python3 /mnt/d/pro/ai_cat/avatar-agent/deploy/wsl2/docker-maintenance.py
python3 /mnt/d/pro/ai_cat/avatar-agent/deploy/wsl2/docker-maintenance.py --apply
```

存储扫描在 PostgreSQL 任务准入锁内进行，发现正在制作的任务就跳过。仅删除数据库中已没有有效归属的 UUID 项目和运行目录；不会按文件年龄删除仍存在的项目素材。`--test-files` 额外清理脚本中列明的旧回归测试、诊断、设计预览目录，不匹配任意名称。

`deploy/wsl2/deploy.ps1 -Service all|backend|frontend` 已接入：

- 构建前清理历史孤立文件，切换后端前继续使用原有任务保护。
- 正常情况下保留实际运行镜像为 `previous`，并保留 `latest` 和固定的运行依赖镜像；服务健康验证后删除其他未使用的本项目应用镜像。
- 清理超过两小时未使用的 Docker 构建缓存。不执行全局镜像清理或数据卷清理。
- 最近三组数据库和配置备份保留，较旧备份删除。
- 当前镜像元数据缺失时输出警告，不将未运行的 `latest` 冒充旧版本；这一轮无法新建准确的回滚标签。新部署成功后，后续更新可恢复正常保留。

WSL 内文件释放与 Windows 上 VHDX 缩小是两回事。需要进一步归还 D 盘物理空间时，在没有任务且允许停止服务的维护窗口执行 trim 和 WSL compact；部署不会自动停掉整个 WSL。

## 验证

后端 `TestProjectCleanup` 覆盖新旧目录、无运行项目、跨用户拒绝、活跃任务/收尾、迟到启动、符号链接、失败重试、积分和关联记录，以及临时目录清理。前端 `projectService.delete.test.ts` 验证服务端成功后清本地缓存、失败时保留。部署脚本的 Python 测试覆盖目录边界和镜像保留策略。

真实部署验收脚本 `deploy/wsl2/verify-project-cleanup.cjs` 创建两个专用测试项目，真实上传文本，注入无模型调用的本地运行文件，从项目列表点击删除，核验数据库、服务器文件、OPFS、IndexedDB 均清理，另一个项目仍可访问，并在结束时删除测试项目。

旧 `frontend/src/pages/ProjectListPage.delete.test.tsx` 仍以旧页面结构编写，当前会因未提供新版 StudioShell 所需的 AuthProvider 而失败；本轮保留其原状，用新版真实页面验收覆盖删除行为。
